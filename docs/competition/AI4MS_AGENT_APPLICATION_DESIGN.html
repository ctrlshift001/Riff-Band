摘要与设计结论

Executive summary and document map

AI4MS 解决的不是“让模型自动写一篇论文”，而是管理科学研究中长期存在的流程断裂问题：检索与选题分离、方法建议缺少假设边界、数据与代码不可追溯、结果与正文失去对应、人工决定没有版本记录。系统将研究过程建模为 S0 至 S9 十个阶段，以结构化资产、不可变 revision、人工 Gate、工具风险等级和证据 ID 贯通全链路。

10阶段智能体，从问题识别到研究交付
28去重后的工具能力，按阶段最小授权
151方法、公式、数据源与诊断知识条目
5+HTML、Word、PDF、图表与 Stata 复现包

核心设计判断

  1. 科研智能体首先是一个受治理的项目系统，而不是一次性聊天窗口。
  2. 模型负责提出候选、综合材料和生成草稿；服务端负责状态、契约、哈希、权限与确定性产物。
  3. 论文、数据、运行结果和主张通过真实 ID 连接，无法核查的内容保留为 unknown。
  4. 高风险工具必须满足前置条件并由人确认，智能体不能自批、伪造运行或发布。
  5. 管理科学是首个领域画像，底层协议可通过知识注册表与 DomainProfile 扩展到其他学科。

拟解决的科学问题与应用背景

From fragmented assistance to auditable research infrastructure

1.1 管理科学研究中的关键断点

选题断点

相邻术语、经典文献和反向证据未被系统检索，容易把“没有搜到”误写成“尚无研究”。

方法断点

模型或方法被按流行度推荐，研究目标、数据形状、识别假设和诊断条件没有共同进入决策。

证据断点

论文、数据、代码、运行日志、稳健性检查与最终结论分别存放，难以复核结论从何而来。

1.2 产品问题定义

本作品将科学问题定义为：如何构建一个面向管理科学的科研智能体系统，使其能够在长周期研究中持续组织多源证据、形成结构化建议、调用受控分析工具并生成可复现交付物，同时避免模型替代研究者作出不可逆学术决定。

目标不是增加自动生成文本的数量，而是提高研究问题、证据、方法、运行与结论之间的可追溯性。

1.3 设计目标

目标系统回应可检查结果
检索可信多来源并集、去重、查询快照、纳排标准和反向检索。paper_id、来源状态、检索时间、覆盖限制。
建议可解释建议绑定研究目标、证据 ID、方法假设、置信度和可推翻条件。reasoning_trace 与候选资产。
计算可复现获批 do-file、数据签名、Runner 环境、结构化结果和 artifact hash 共同构成 Run。Run Bundle / Result Bundle。
人类可控制关键阶段设置人工 Gate，高风险工具需要明确确认。approval event、revision/hash、审批理由。
成果可交付同一结构化研究资产生成 HTML、Word、PDF、图表与复现包。manifest、版本号、下载产物。

1.4 目标用户

主要用户包括管理科学研究者、导师、方法审核者、数据负责人和复现检查人员。产品采用本地优先架构，适用于个人课题、导师组协作和需要保留研究过程证据的课程或竞赛场景。

总体技术架构

One browser entry, typed services, persistent research assets

AI4MS 使用浏览器 GUI 作为唯一产品入口，Next.js 静态前端与 FastAPI 在 Docker 中通过同一端口交付。科研事实由服务层、SQLite 和项目资产目录共同维护，模型不能直接改写状态或伪造执行结果。

服务端职责

  • 阶段解锁、状态流转、revision 与 approval；
  • Pydantic 契约和项目内 ID 白名单；
  • 数据 SHA-256、Run 签名和产物哈希；
  • 后台任务、超时、取消、重跑与结果解析；
  • 报告、图表、Mermaid 和复现包确定性生成。

模型职责

  • 澄清问题、规划查询、综合已有材料；
  • 比较理论、方法、数据和风险候选；
  • 提出稳健性、机制、异质性和反证检查；
  • 基于已批准主张生成可编辑写作草稿；
  • 信息不足时显式输出 unknown 与下一步核验。
核心边界： LLM 输出先作为不可信候选数据进入校验链；项目状态、审批结果、正式数值、发布状态和文件路径均由后端生成。
02 · 总体架构
03

智能体体系与动态编排

Stage agents plus on-demand sub-agent orchestration

3.1 两层智能体结构

阶段主智能体

每个 S0-S9 阶段拥有固定使命、必需输入、管理科学检查、工具清单、停止条件和禁止行为。它负责形成可进入人工审阅的结构化草稿。

动态 SubAgent

在复杂检索与证据审计阶段，MainAgent 根据任务临时创建专门执行者，控制它看到的上下文、可调用工具和模型，完成后回收报告。

3.2 原论文基础

底层动态编排思想基于论文 AOrchestra: Automating Sub-Agent Creation for Agentic Orchestration （Ruan 等，2026，arXiv:2602.03786）。原论文把可动态创建的智能体抽象为四元组：

Instruction当前子任务、完成标准、禁止事项与返回结构。
Context与子任务相关的最小项目材料，避免全量上下文噪声。
Tools按风险和阶段边界选择的工具集合，不继承全部权限。
Model可替换的模型配置，用于平衡质量、时延与成本。

AI4MS 在此思想上增加科研协议和治理层：SubAgent 输出不能直接成为项目事实，必须回到阶段主智能体，经结构契约、证据 ID、权限和人工 Gate 检查后才能保存。

3.3 本项目的编排落点

阶段动态任务权限约束失败处理
S0-S1边界澄清、检索侦察、研究流派、反向检索和覆盖审查。允许受控公开检索，保存来源与时间。30 秒预算超时后记录降级状态，继续直接结构化生成。
S7-S8稳健性、负结果、Claim-Evidence 和过度主张审查。只读项目内论文、计划和成功 Run；禁止联网和启动 Runner。保留失败与冲突，不允许降级为无证据高置信结论。

论文与代码： arXiv:2602.03786； FoundationAgents/AOrchestra。

03 · 智能体设计

S0-S9 十阶段科研协议

A continuous research state machine with human gates

十个阶段共享同一个 ProjectState。每阶段读取已批准或当前上游资产，生成结构化草稿，允许研究者编辑、接受或拒绝，并以新 revision 保存。上游关键内容改变时，下游批准会失效，防止旧结论继续沿用。

理论视角、构念、机制、竞争解释与可证伪命题。		TheoryModel选择理论和贡献边界。

分析单位、主备设计、假设、威胁和停止条件。		ResearchProtocolG1 批准研究设计。

S5Method Agent
estimand、模型规格、诊断、代码和复现要求。		AnalysisPlanG3 冻结计划与 do-file。

04 · 十阶段协议
05

工具、联网检索与领域知识

Typed tools, multi-source retrieval, and management science registries

5.1 多源科研检索

查询规划中英文术语、相邻概念、排除词、反向查询
->
并行来源OpenAlex、Crossref、Semantic Scholar、arXiv、Serper、DuckDuckGo
->
规范化URL/DOI、标题作者、稳定 paper_id、去重与来源状态
->
证据综合研究流派、共识、争议、覆盖限制和候选空白

阶段对话支持 auto / on / off 三种联网模式。网页和 PDF 内容被视为不可信数据，系统拒绝本机、私网和非 HTTP(S) 地址，限制重定向与响应体大小，并把来源编号与回答一起保存。

5.2 MCP 与官方数据

连接器层使用 MCP Streamable HTTP 接入 Google Data Commons，只放行 search_indicators 和 get_observations 两个只读工具。MCP 未配置或不可用时，不阻塞普通学术与网页检索，并明确显示连接状态。

5.3 管理科学知识注册表

28方法卡：适用目标、数据形状、假设、诊断与 Stata 映射
47公式卡：符号、变量角色、条件和实现提示
40数据源卡：可得性、许可、粒度、更新和风险
36诊断规则：触发条件、严重度、停止或降级动作

注册表不是静态展示数字。阶段智能体基于当前草稿和研究目标评估候选，前端展示适配理由、假设缺口和所需人工判断。模型只能从返回的 method_id、formula_id 和 source_id 中选择。

5.4 工具风险分级

R0只读本地元数据或注册表，不产生持久化变更。
R1检索公开信息或读取项目资产，必须记录来源与时间。
R2生成或修改草稿与 revision，可撤销并标记 AI 来源。
R3执行代码或计算，要求隔离、限时、可取消、保留日志。
R4导出正式交付或改变审批状态，必须由人明确确认。
R5权限、密钥、安全策略或不可逆动作，阶段智能体禁止自主调用。

当前注册 10 个阶段 Policy、34 个阶段工具绑定、28 个去重工具能力；R5 不向阶段智能体开放。

长期记忆、资产版本与证据链

Research memory is a typed project state, not a chat transcript

6.1 项目记忆模型

AI4MS 不把长对话历史当作唯一记忆。长期项目事实被拆成可寻址对象：阶段 revision、论文、数据资产、审批事件、分析 Run、结构化结果、Claim-Evidence 和导出记录。SQLite 保存状态索引，项目目录保存不可变文件产物。

AI4MS_DATA_DIR/ ai4ms.db projects/<project_id>/ artifacts/ literature/ search/ chat/ data/ jobs/ runs/ exports/

6.2 不可变 revision 与人工决定

读取基准客户端携带 expected revision，避免覆盖他人更新。
生成变更人工编辑、Agent 草稿或选定建议形成新内容。
计算哈希服务端规范化内容并生成 content hash。
追加版本保存作者类型、变更理由、时间与来源。
绑定审批人工决定只批准确定 revision/hash。

6.3 Claim-Evidence 可追溯模型

Paper / Data真实来源、许可、paper_id 或 asset_id
->
Run / Artifact输入哈希、do-file、结构化结果、日志与图表
->
Claim方向、强度、范围、假设、置信度与反证
->
Report每项结论绑定 claim_id 与 evidence_id
资产可修改方式禁止行为
阶段草稿创建新 revision，保存 diff 与变更理由。静默覆盖已批准内容。
论文元数据更正来源、添加 annotation 或重新检索。模型补造 DOI、作者或结论。
数据与 Run登记新资产或执行新 Run。改写原始数据、日志和正式数值。
人工批准追加 approve、request changes 或 reject 事件。Agent 自批或把提示文本解释为批准。
记忆压缩原则： 进入下一阶段时只注入必要上游对象和紧凑证据摘要；完整资产保留在项目目录，可由 ID 回查，避免长上下文污染和样例术语串扰。
06 · 记忆与证据
07

提示词工程与可信控制

Contract-first generation, least privilege, and human responsibility

7.1 契约优先的生成链

Prompt Catalog 当前包含 11 个版本化提示词：S0-S9 共 10 个阶段，其中 S1 在检索前使用“查询计划”提示词，保存真实论文后切换为“证据综述”提示词。每次合格生成记录模型、prompt ID、版本、时间、尝试次数和 token 用量，不记录密钥。

7.2 可审计推理而非私密思维链

草稿要求输出 reasoning_trace，记录问题框定、evidence_ref、推断类型、结论、置信度、falsifier、待人工决定和下一步核验。系统不请求或保存 token 级内部思维过程。

7.3 主要防线

风险控制机制失败时表现
虚构论文或数据只接受输入中存在的 paper_id、source_id、run_id 与 artifact_id。返回结构/引用错误，不保存 revision。
提示词注入网页、论文、附件和工具结果统一标记为不可信数据，不能覆盖系统规则。忽略恶意指令并保留来源。
模型服务波动主备模型、请求超时、有限重试、结构修复和可追踪错误编号。明确 502/503 或降级，不伪造成功。
越权执行工具按 R0-R5 分级，R3/R4 要求人类确认，R5 禁止自主调用。blocked 并列出缺失前置条件。
过度主张S8 强制记录反证、限制和置信度；S9 只能使用 G4 已批准主张。降低主张强度或阻止导出。

7.4 人工 Gate

G0 选题、G1 设计、G2 数据、G3 分析计划、G4 解释边界、G5 发布均由研究者完成。审批事件绑定 revision 与 hash，Agent Policy 中不存在可写入 approved 的输出字段。

07 · 可信与门禁
08

数据资产与 Stata 可复现执行

Docker workbench connected to a licensed local runner

Stata 属于商业软件，不能进入比赛镜像。AI4MS 采用 BYOL 模式：Docker 工作台通过配对令牌连接研究者本机合法安装的 Local Runner，将获批分析计划转化为签名执行包，并回收机器可读 Result Bundle。

8.1 数据登记

上传 `.dta` 后登记 asset_id、原文件名、不可变项目路径、文件大小、SHA-256、Stata 格式版本、数据标签、行列数，以及变量名、标签、存储类型、显示格式和值标签。Preflight 只接受项目内 asset_id，不接受浏览器提交任意宿主机路径。

8.2 Run Bundle / Result Bundle

工作台发送

run_request.json analysis.do entrypoint.do result_contract.do input.dta

Runner 返回

result_bundle.json structured_results.csv data_signature.txt analysis.log *.csv / *.xlsx *.png / *.svg / *.pdf

8.3 执行可靠性

  • 后台状态覆盖 queued、running、canceling、succeeded、failed、canceled 和 interrupted。
  • 超时范围 1-7200 秒；取消信号继续传递到 Local Runner 和活动 Stata 进程。
  • 重跑记录 parent_run_id，并重新执行 Preflight，不复用过期批准或数据签名。
  • 退出码为 0 但缺少 structured_results 时仍判定失败。
  • 失败、取消和负结果保留最小 manifest，不能被写作层隐藏。
`.dta`、Stata 安装文件、许可证与序列号不进入镜像、返回包或最终研究交付包。
08 · Stata 执行
09

GUI 与多格式研究交付

One project state, multiple review and publication formats

9.1 科研工作台界面

首屏直接进入真实项目工作台，不设置营销落地页。主要视图包括十阶段研究旅程、阶段草稿与版本历史、审批中心、证据库、方法与公式库、数据资产、Runner 状态、智能体对话、报告预览和导出中心。

9.2 S9 多格式输出

格式用途关键内容
交互 HTML浏览器审阅与答辩演示。目录、结论、证据回链、图表筛选、Claim-Evidence 图和披露。
Word研究者继续编辑和团队批注。与结构化资产一致的标题、正文、表格、引用和限制。
PDF固定版本、提交和归档。确定版式、中文字体、版本信息和审计摘要。
图表与 Mermaid展示研究流程、结果和证据关系。JSON、SVG、PNG 与 `.mmd` 源码。
Stata 复现包复核分析环境与结果。获批 do-file、结构化结果、日志、数据签名、Runner 信息和 manifest。
综合研究包一次性归档完整交付。上述产物、引用元数据、版本和 SHA-256 清单。

9.3 确定性生成原则

S9 模型只负责形成结论候选、政策含义和写作结构；文件路径、图表数据、参考文献、manifest、版本和 hash 由服务端从 G4 已批准的主张、真实论文与成功 Run 确定性生成。任何未批准主张、未知 paper_id 或无结构化结果的 Run 都不能进入正式结论。

HTML、Word、PDF 和 Stata 包来自同一版本化研究状态，避免不同格式之间出现数字、引用或结论不一致。

10

预期成果、创新点与多学科泛化

What is new in the application design

01

从聊天助手转向科研状态机

把问题、论文、理论、设计、数据、运行、主张和报告建模为连续项目资产，使智能体建议能够被保存、审查、回滚和复用。

02

AOrchestra 动态编排与科研 Gate 的结合

按任务动态创建 SubAgent，但用阶段契约、工具最小权限、证据 ID 和人工 Gate 限制其进入科研事实层的方式。

03

反向检索与不利证据优先

系统不仅搜索支持候选空白的材料，还主动寻找最可能推翻它的相邻研究；稳健性失败、负结果和冲突证据不能被隐藏。

04

面向商业统计软件的合法本地执行桥

Docker 不分发 Stata，通过签名 Bundle 连接用户自有许可环境，将代码审批、数据签名、结构化结果和取消重跑纳入同一证据链。

05

主张级可追溯的多格式交付

报告不是孤立文本，而是已批准 Claim、论文、Run、图表和审批事件的视图；HTML、Word、PDF 和复现包共享同一事实来源。

06

领域垂直与跨学科扩展并存

管理科学能力由 DomainProfile、方法库、公式库、数据源库、诊断规则和阶段 Policy 注入，通用 Runtime、revision、审批与证据协议保持稳定。

10.1 多学科泛化策略

保持稳定按学科替换或扩展目标
阶段状态、revision、approval、artifact、Claim-Evidence、工具风险与模型网关。DomainProfile、研究范式、方法/公式/数据源注册表、Gate 检查与提示词。不复制整套系统即可扩展到运筹优化、公共管理、信息系统、定性研究或其他科研领域。

10.2 预期成果

  • 一个可由评委本地部署、通过浏览器直接使用的完整科研智能体产品。
  • 一条从研究想法到可交互报告与复现包的 S0-S9 端到端工作流。
  • 可审计的文献检索、科研建议、人工审批、真实计算与证据回链能力。
  • 可复用于其他学科的 Agent Runtime、工具策略和结构化科研资产协议。

评审演示路径、适用边界与参考

Suggested judging flow and transparent limitations

12.1 建议演示路径

  1. 启动：运行 START_AI4MS，查看镜像、健康、模型和搜索探针通过后进入工作台。
  2. S0：输入一个管理科学研究想法，调用 Topic Agent 形成问题边界、候选空白和反向检索。
  3. S1：执行真实多源检索，观察证据库从空状态生成论文记录、查询快照与已有研究报告。
  4. S2-S5：查看理论、研究设计、数据合同、方法/公式建议和分析计划如何引用上游真实资产。
  5. 人工门禁：编辑草稿、保存人工决定、提交审批并查看 revision/history 与阶段实时进度。
  6. S6：查看 `.dta` 元信息、Runner 状态、Preflight、后台任务和 Result Bundle；无 Stata 时应明确 blocked。
  7. S7-S8：从成功 Run 生成稳健性和 Claim-Evidence，检查负结果、反证与限制未被隐藏。
  8. S9：预览交互 HTML，并下载 Word、PDF、图表、Mermaid、Stata 复现包和综合研究包。

12.2 适用边界

边界当前设计
科学责任系统提供候选、检查与证据组织，不保证绝对原创，也不替代研究者承担结论责任。
部署规模比赛版面向单用户、单 FastAPI 进程、SQLite 和本地文件系统，不宣称组织级多租户。
外部来源检索结果受网络、数据库覆盖和提供方可用性影响，系统保存覆盖限制而非宣称穷尽。
商业软件Stata 必须由用户或机构合法提供；无 Runner 时分析保持 blocked，不显示模拟结果。
敏感数据受限数据默认不发送给外部模型；机构场景仍需使用专用账户、计算节点和防火墙策略。
